## Overview

Implementasi fitur login user dengan session tokens berbasis UUID dan password verification menggunakan bcrypt.

## Changes

### Database
- Buat tabel sessions: id, token (UUID), user_id (FK ke users), created_at
- Migrasi `0002_create_sessions.sql` berhasil diterapkan ke Supabase

### New Features
- **loginUser function** di src/services/users-service.ts
  - Email lookup
  - Password verification dengan Bun.password.verify
  - UUID token generation
  - Session save ke database
  - Security: same error message untuk email salah dan password salah
  
- **POST /login route** di src/routes/users-route.ts
  - Input validation (email, password required)
  - Return token dalam format { data: "<uuid>" }
  - HTTP status 401 untuk login gagal
  - Error handling dan logging

### Modified Files
- **src/schema.ts** — Add sessions table definition
- **src/services/users-service.ts** — Add loginUser function with imports
- **src/routes/users-route.ts** — Add POST /login handler
- **drizzle/0002_create_sessions.sql** — Migration file
- **drizzle/meta/_journal.json** — Update migration journal

### Testing
✅ Successful login returns token
✅ Wrong password returns error 401
✅ Non-existent email returns same error (security)
✅ Each login generates unique token
✅ Sessions saved to database with correct user_id
✅ Other endpoints still work (/health, /api/users)

## API Endpoint

### POST /api/users/login

Login user dan dapatkan session token

**Request:**
```json
{
  "email": "eko@localhost",
  "password": "rahasia"
}
```

**Success Response (200):**
```json
{
  "data": "561283a0-4b9a-4da2-9aa1-e1026d41adb5"
}
```

**Error Response (401):**
```json
{
  "error": "Email atau password salah"
}
```

## Tech Details

- Token generation: crypto.randomUUID() (Bun built-in)
- Password verification: Bun.password.verify with bcrypt
- Database: PostgreSQL Supabase
- No additional dependencies needed
